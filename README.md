# MLOps Labs

FastAPI-сервис с проверками состояния и CI/CD в GitHub Actions.

## Логирование

Приложение пишет JSON-записи в stdout. Настройка находится в
`src/mlops_labs/core/logging.py` и вызывается один раз при запуске приложения.
Новые зависимости для логирования не нужны.

Уровень задаётся переменной `LOG_LEVEL`: `DEBUG`, `INFO` (по умолчанию),
`WARNING`, `ERROR` или `CRITICAL`. Docker Compose передаёт её приложению.

Для запуска и просмотра логов из корня проекта:

```powershell
docker compose up -d --build --wait --wait-timeout 120
Invoke-RestMethod http://localhost:8000/api/v1/version
docker compose logs --tail 30 app
```

Пример записи (время и длительность условные):

```json
{"timestamp":"2026-09-25T10:00:00.000+00:00","level":"INFO","logger":"mlops_labs.main","event":"http.request","method":"GET","route":"/api/v1/version","status_code":200,"duration_ms":1.2}
```

События `app.started` и `app.stopped` обозначают запуск и остановку приложения.
В событии запуска также указана версия. Для каждого запроса формируется одна
запись `http.request`: ответы 4xx имеют уровень `WARNING`, 5xx — `ERROR`.
Успешные обращения к `/healthz` имеют уровень `DEBUG`, чтобы регулярные
проверки Docker не заполняли журнал на уровне `INFO`.

`duration_ms` измеряет время до получения ответа от обработчика; время передачи
всего потокового ответа клиенту сюда не входит. Маршрут записывается как шаблон
(например, `/items/{item_id}`), неизвестный маршрут — как `<unmatched>`.
Тела запросов, заголовки и параметры URL в лог не попадают.

Ошибки проверок зависимостей записываются как `dependency.unavailable` или
`dependency.check_failed` с именем зависимости и типом ошибки. Исходный текст
этих исключений не выводится, поскольку он может содержать данные подключения.
Неожиданную ошибку обработчика фиксирует Uvicorn: JSON-форматтер сохраняет тип
исключения и места в стеке вызовов без текста исключения и строк исходного кода.
Эта диагностическая запись дополняет запись о запросе со статусом 500.
Не следует вручную добавлять секреты в сообщения `logger` или поля `extra`.

Стандартный access log Uvicorn отключён, поскольку запросы уже записывает
приложение. Начальные сообщения Uvicorn до запуска приложения ещё могут иметь
стандартный текстовый формат; после настройки используется JSON.

Для запуска без Docker после установки зависимостей:

```powershell
uv run uvicorn mlops_labs.main:app --host 127.0.0.1 --port 8000 --no-access-log
```

Если `uv` не добавлен в PATH, в этой рабочей папке вместо `uv` можно использовать
`& "..\.mlops-tools\uv\uv.exe"`. Для успешной проверки `/api/v1/health` нужно
также задать `DATABASE_URL`, указывающий на доступную PostgreSQL.

## Проверка пункта 13

1. Выполнить `uv run pre-commit run --all-files` и
   `uv run pytest --cov=mlops_labs --cov-report=term-missing`.
2. Установить локальный hook командой `uv run pre-commit install`, если он ещё
   не установлен. При коммите он проверит добавленные в индекс файлы.
3. После коммита и push открыть GitHub Actions и проверить оба задания:
   `Lint, format, types, tests and coverage` и `Build, smoke test and publish`.
   Публикация образа выполняется при push в `main` или при подходящем теге `v*`.
4. Сохранить вывод успешного pre-commit и ссылку на успешный запуск Actions.
   Артефакты `test-reports` и `container-logs` содержат результаты тестов и логи
   контейнеров, в том числе проверки работы с недоступной БД.

Полный цикл подтверждается результатами конкретного коммита и запуска Actions.
Одной локальной проверки недостаточно для подтверждения публикации образа.
